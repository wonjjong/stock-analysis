# 품질 정책

## 필수 검증

코드·마이그레이션 변경 전후에는 `backend/`에서 다음을 실행한다.

```bash
.venv/bin/python -m pytest
.venv/bin/ruff check .
```

DB를 쓰는 테스트는 `signalist_test` 데이터베이스를 사용한다. 개발 DB와 분리되어야 하며, 검증 때문에 운영·개발 데이터를 삭제하거나 초기화하지 않는다.

## 뉴스 파서 parity

뉴스 크롤러는 동결된 출력 정답지 `backend/news/tests/parity/expected.json`와 동작을 비교한다. 날짜, URL, HTML/피드, 수집 창, 스케줄, 분석, 본문, LLM 실패 분류, 종목 매칭이 대상이다.

- 동작 변경이 아닌 리팩터링은 parity 결과를 바꾸지 않아야 한다.
- URL 정규화, 날짜 판독, 본문 추출, 감성·점수 계산 변경은 parity 실패를 단순히 갱신해서 넘기지 않는다. 기존 기사 식별자·수집량·분석 결과에 미치는 영향을 먼저 판단한다.
- 의도된 계약 변경은 변경 이유, 데이터 백필/재처리 필요성, 새 고정 입력을 함께 검토한 뒤 정답지를 갱신한다.

## 테스트 수준

| 수준 | 대상 | 예 |
| --- | --- | --- |
| 순수 단위/parity | `crawler`, `research` | 날짜 오인 방지, URL 표준화, LLM 값 검증, 랭커 결정성 |
| 통합 | Django·PostgreSQL 경계 | 핵심 테이블 접근성, 마이그레이션 결과 |
| 네트워크 모의 | HTTP 수집 어댑터 | robots, 리다이렉트, 크기 상한, 304 |

새 도메인 규칙은 가능한 한 순수 테스트로 먼저 고정한다. 외부 서비스 호출을 실제 키·실제 뉴스 사이트에 의존하는 테스트로 만들지 않는다.

## 문서 품질

- 현재 구현과 목표 설계를 같은 문단에서 섞지 않는다.
- 명령, 상태값, 경로, 상한은 코드에서 확인한 값만 쓴다.
- 기능·상태 전이·스키마·운영 절차가 바뀌면 관련 도메인 및 정책 문서를 같은 변경에서 수정한다.
