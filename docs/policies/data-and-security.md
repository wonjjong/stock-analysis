# 데이터·보안 정책

## 수집 대상과 보존

- 운영자가 등록한 공개 뉴스 목록, RSS, Atom만 수집한다. 로그인·유료·내부망 대상은 지원 범위가 아니다.
- 종목 분석 요청에서는 고정된 Naver/GDELT 검색 API와 Yahoo 종목 뉴스도 조회한다.
  이 경로는 제목·요약·URL·시각만 20분 캐시하고 원문 URL의 본문은 요청하지 않는다.
- robots.txt 판정을 존중한다. 목록 수집에서 401·403·5xx는 허용 여부를 확인할 수 없는 것으로 보고 실행을 중단한다. 404 등은 규칙 없음으로 본다.
- 저장하는 원본 정보는 제목, 목록 요약, 표준 URL, 발행·수집 시각이다. 기사 본문은 분석 입력으로 읽을 수 있지만 DB에는 저장하지 않고 글자 수와 파생 분석만 저장한다.
- 원문 삭제·저작권 요청 처리 절차와 보존 기간은 현재 코드에 구현되어 있지 않다. 실제 서비스 운영 전 담당자, 접수 채널, 삭제 범위, 보존 기간을 결정해야 한다.

## 외부 URL 안전성

- 허용 스킴과 호스트 형식을 검증하고 private IPv4/loopback 대상은 거부한다.
- 리다이렉트는 자동 추종하지 않으며 최대 3회, 매 홉 URL 검증을 수행한다.
- 목록 응답은 12초 전체 데드라인과 2.5MB 상한을 적용한다. 본문 분석용 응답은 12초와 1.5MB 상한을 적용한다.
- 현 구현은 DNS 해석 결과 검사와 IPv6 특수 범위 검사를 하지 않는다. 이는 URL 안전성의 남은 공백이다. 외부 입력을 더 넓게 허용하기 전 별도 하드닝과 회귀 테스트가 필요하다.

## 개인정보와 비밀값

- 현재 도메인 모델에는 사용자 개인정보를 수집하는 필드가 없다.
- LLM API 키는 `LlmProvider.api_key` 또는 환경변수로 제공된다. 화면과 Admin의 목록 표시는 끝 네 글자만 노출하지만, DB에는 평문으로 저장된다.
- `.env`는 저장소에 커밋하지 않는다. 배포 시 `DJANGO_SECRET_KEY`, `DATABASE_URL`, 허용 호스트, LLM 키를 안전한 런타임 시크릿으로 주입한다.
- DB 암호화, 키 순환, 감사 로그, 비밀 관리자 연동은 현재 구현되어 있지 않다. 운영 환경에서는 최소 권한 DB 계정과 시크릿 관리 방식을 별도로 확정해야 한다.

## 접근 통제

- Django Admin은 Django 인증을 사용한다.
- 뉴스 대시보드·소스·공급자·분석 화면에는 현재 별도의 인증/인가 데코레이터가 없다. 변경 요청은 CSRF 미들웨어와 템플릿 토큰으로 보호되지만, 이는 사용자 권한 검증이 아니다.
- 그러므로 인터넷에 공개 배포하기 전에는 최소한 운영 화면과 변경 경로에 인증·인가를 추가하고, `/healthz`의 테이블 건수 노출 범위도 재검토해야 한다.
