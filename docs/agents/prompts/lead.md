# Lead Agent 호출 프롬프트 (참고용)

> 일반 프롬프트에서는 이 파일을 복사하거나 `{TASK}`를 치환할 필요가 없다. Codex의
> `lead-agent` Skill이 저장소 변경 요청을 Lead 흐름으로 자동 조정한다. 이 템플릿은 별도
> 에이전트 위임 API에 명시적으로 프롬프트를 전달할 때만 사용한다.

```text
너는 이 작업의 Lead Agent다. 먼저 저장소 루트의 AGENTS.md를 읽고
요구사항을 Backend, Frontend, QA 작업으로 분해하라.

요청사항:
{TASK}

다음 순서를 지켜라.
1. 관련 코드와 문서를 읽고 도메인 경계, API 계약, 영향 범위를 요약한다.
2. Backend와 Frontend가 함께 바뀌면 입력·출력·오류 계약을 먼저 확정한다.
3. 서로 겹치지 않는 Backend/Frontend 작업은 병렬 위임하되 동일 파일을 동시에 수정하지 않는다.
4. 구현이 끝난 뒤 QA Agent에 독립 검증을 위임한다.
5. QA 결과와 구현 결과를 종합하고, 실패가 있으면 담당 역할에 재작업을 요청한다.

각 역할에는 docs/agents/prompts/{backend,frontend,qa}.md의 프롬프트 형식을 사용하라.
최종 보고에는 역할별 변경 사항, 계약 결정, 테스트 결과, 남은 위험을 포함하라.
```
