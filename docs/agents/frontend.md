# Frontend Agent 지침

## 책임

- 현재 저장소의 Django templates와 `backend/news/static/` 자산을 담당한다.
- 백엔드 API와 서버 렌더링 컨텍스트를 소비하는 화면, 상호작용, 폼, 오류 표시를 구현한다.
- 사용자가 이해할 수 있는 상태(loading, empty, error, success)를 일관되게 표현한다.

## 작업 규칙

1. 먼저 관련 view, form, URL, template, static 파일과 API/도메인 문서를 읽는다.
2. 백엔드 계약을 추측하지 않는다. 필요한 입력·출력·오류 형식이 불명확하면 Lead/Backend에 계약을 요청한다.
3. 템플릿에 비즈니스 규칙이나 DB 조회를 추가하지 않는다. 표시용 변환만 수행한다.
4. 기존 디자인 언어와 접근성 패턴을 유지한다. 의미 있는 HTML, 키보드 탐색, label, focus 상태를 확인한다.
5. CSS/JS 변경은 해당 화면에 필요한 최소 범위로 제한하고 전역 스타일 오염을 피한다.
6. 서버 렌더링 경로, 권한 없는 사용자, 빈 데이터, 오류 응답을 함께 확인한다.

## 완료 기준

- 관련 화면의 정상·빈 상태·오류 상태를 확인한다.
- 백엔드 API 계약과 불일치하는 임의의 fallback을 추가하지 않는다.
- 변경 파일과 수동 확인 방법을 최종 보고에 포함한다.
- 가능하면 템플릿 렌더링 테스트 또는 기존 테스트를 실행한다.

## 주의

이 저장소에는 별도의 SPA 빌드 체인이 없을 수 있다. 새로운 프론트엔드 프레임워크나 패키지를
추가하기 전에 기존 템플릿/static 구조로 해결 가능한지 먼저 검토하고, 추가가 필요하면 이유와
운영·빌드 영향을 보고한다.
