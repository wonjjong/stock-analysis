# 도메인 개요

Signalist는 뉴스와 요청 기반 종목 리서치 경계를 제공한다. 아래 구분은 디렉터리 편의가 아니라 변경 이유와 데이터 소유권을 분리하기 위한 기준이다.

| 경계 | 책임 | 현재 상태 | 주요 코드 |
| --- | --- | --- | --- |
| 뉴스 | 공개 뉴스 수집, 기사 분석, 종목 연결, LLM 공급자 운용 | 구현됨 | `backend/news/` |
| 리서치 | 종목 검색, 시장·공시·뉴스 근거 분석, 팩터·거시 랭킹 | 구현됨(요청 기반) | `backend/research/` |
| 플랫폼 | HTTP, 템플릿, 설정, DB 접속, Django Admin | 구현됨 | `backend/signalist/` |

## 공통 언어

| 용어 | 뜻 |
| --- | --- |
| 소스 | 수집을 허용한 뉴스 목록, RSS 또는 Atom URL과 실행 설정 |
| 기사 | 소스에서 식별한 목록 항목. `canonical_url`로 식별한다. |
| 수집 실행 | 소스 하나를 대상으로 한 한 번의 시도 및 결과 이력 |
| 인사이트 | 기사 제목·요약 또는 본문에서 만든 구조화된 파생 분석 |
| 종목 연결 | 분석된 기사와 종목 사전 항목 간의 관계 |
| 공급자 | OpenAI 호환 Chat Completions 엔드포인트와 모델·한도 설정 |
| 후보 종목 | 리서치 랭커가 시장 데이터에서 만든 팩터 평가 입력 레코드 |
| 근거 | 시장·공시·뉴스 데이터에서 만든, 시각과 출처가 있는 리서치 보고서 입력 |
| 기준 시점(as-of) | 근거가 관측·수집된 시점. 요청 기반 화면에 표시·전달한다. |

## 경계 규칙

- `news/crawler/`는 Django ORM, HTTP 요청 객체, PostgreSQL에 의존하지 않는 파싱·판정 영역이다. 단, 호출자가 수명을 관리하는 `httpx.Client`를 받는 수집 어댑터는 이 안에 있다.
- `news/services/`는 DB 쓰기, 네트워크 호출 순서, 큐 처리, 공급자 페일오버를 조정한다.
- `views.py`, `forms.py`, `admin.py`는 입출력 변환과 호출 조정만 담당한다. 새 도메인 규칙을 이 위치에 넣지 않는다.
- `research/recommendation.py`는 표준 라이브러리만 쓰는 순수 계산 모듈이다. 뉴스 모델이나 Django 모델을 직접 참조하지 않는다.
- 리서치는 저장된 뉴스 인사이트를 근거로 조회할 수 있지만, 외부 API 응답은 시장·공시·뉴스 근거 모델로 변환한 뒤 보고서 생성기에 전달한다.

## 현재 데이터 흐름

```text
뉴스 사이트/RSS → 뉴스 수집 → 기사 → 본문 분석 → 인사이트·종목 연결
                                      └→ LLM 공급자(선택)

가격·재무·거시 데이터 ──────────────→ 리서치 후보·근거 → 종목 분석·랭킹
뉴스 인사이트 ──────────────────────↗
```

리서치 결과는 현재 요청 시에만 만들며 DB에 이력으로 저장하지 않는다.
