# 뉴스 도메인

## 목적과 범위

뉴스 도메인은 운영자가 등록한 공개 뉴스 목록에서 최근 기사를 수집하고, 기사별로 규칙 기반 또는 LLM 보강 분석을 만들어 검색·운영 화면에 제공한다. 원문 본문은 분석 입력으로만 사용하며 저장하지 않는다. 투자 판단이나 매매 신호를 생성하지 않는다.

## 핵심 모델과 불변 조건

| 모델 | 책임 | 코드로 보장되는 조건 |
| --- | --- | --- |
| `NewsSource` | 수집 대상과 주기·수집 창·조건부 요청 캐시 | URL은 유일하다. 활성 소스만 수집한다. |
| `NewsCrawlRun` | 한 번의 수집 시도 관측 | 소스에 연결된다. 실행 전 `실행 중` 행을 먼저 남긴다. |
| `NewsArticle` | 목록에서 얻은 기사 및 경량 분석 | `canonical_url`은 유일하다. KST 게시일은 DB 생성 열이다. |
| `NewsInsight` | 본문 기반 구조화 분석 | 기사당 하나(`OneToOne`)이며 재분석은 upsert한다. |
| `NewsArticleSymbol` | 기사와 종목 사전 항목의 연결 | 같은 기사에 같은 종목은 하나만 둔다. |
| `LlmProvider` | 외부 모델 호출 순서·한도·상태 | 이름은 유일하며 낮은 `priority`부터 후보가 된다. |

`published_date_kst`는 `published_at`이 없으면 `collected_at`을 이용해 PostgreSQL이 계산한다. 애플리케이션은 이 열에 값을 쓰지 않는다. 기사 중복 방지의 기준은 제목 해시가 아니라 URL 정규화 후 `canonical_url`이다.

## 유스케이스

### 1. 소스 등록과 수집

1. 운영자가 `/news/sources`에서 URL, 수집 시각(KST), 페이지 수, 수집 창을 등록한다.
2. 폼은 `validate_source_url`로 URL을 검증하며, 같은 함수가 실제 수집에서도 적용된다.
3. 새 소스는 즉시 한 번 수집한다. 중복 URL이면 새 소스를 만들지 않는다.
4. `crawl_source`는 먼저 `NewsCrawlRun(실행 중)`을 커밋한 후 네트워크 I/O를 수행한다.
5. 최근 창 안의 항목만 저장하고, 동일 URL은 `INSERT ... ON CONFLICT DO NOTHING`으로 무시한다.
6. 소스와 실행 이력은 짧은 트랜잭션에서 성공·변경 없음·빈 결과·오류로 마감하고 다음 실행 시각을 갱신한다.

실행 상태는 `실행 중`, `완료`, `변경 없음`, `새 기사 없음`, `오류`다. 30분을 넘긴 `실행 중` 행은 스케줄러가 오류로 닫는다. 이 동작은 프로세스 비정상 종료 후 관측 상태가 영구히 남는 것을 막는다.

### 2. 목록 파싱과 선정

- RSS/Atom이면 피드를 우선 파싱한다. HTML이면 JSON-LD와 링크 주변 문맥에서 기사·발행일을 찾고, 페이지의 RSS 링크도 발견하면 시도한다.
- HTML 페이지네이션은 설정값과 절대 상한 중 작은 값(최대 10페이지)까지만 최신순으로 진행한다. 수집 창 안의 기사가 없는 페이지가 나오거나 다음 URL이 반복되면 멈춘다.
- 항목은 최대 200개로 제한하며, 발행시각이 없는 항목은 저장하지 않는다. 수집 창 기본값은 36시간, 허용 범위는 6~168시간이고 미래 발행시각은 최대 2시간까지만 허용한다.
- URL 정규화는 추적 파라미터를 제거하고 URL을 표준화한다. 이는 기존 기사 식별자와 연결된 영구 계약이므로 strip 규칙 변경에는 재정규화·중복 검토가 필요하다.

### 3. 본문 분석 큐

새 기사는 `insight_status=대기`로 들어간다. `process_pending_insights`는 최신 게시시각 순으로 1~50개(기본 12개)를 가져와 아래 순서를 수행한다.

1. 원문 URL에서 허용된 본문을 가져온다. 실패하면 저장된 요약으로 계속 분석한다.
2. 규칙 엔진이 감성, 중요도, 사건 유형, 키워드, 종목 연결을 먼저 만든다.
3. 종목이 잡혔거나 중요도가 낮지 않거나 본문이 1,200자 이상이면 LLM 보강을 시도한다.
4. 성공 결과는 인사이트 upsert 및 종목 연결 교체와 함께 저장하고 기사를 `완료`로 바꾼다.
5. 처리 자체가 실패하면 시도 횟수와 오류를 기록한다. 3회 미만이면 `대기`, 3회 이상이면 `오류`다.

모든 LLM 공급자가 실패해도 규칙 결과를 저장하며 해당 기사는 완료된다. 이는 외부 AI의 가용성이 뉴스 파이프라인 전체를 멈추게 하지 않는 계약이다. LLM 응답은 길이·목록 수·허용 값·수치 범위를 검증하고, 올바르지 않은 필드는 규칙 기반 값으로 대체한다.

## 외부 연동 안전 경계

목록 수집과 본문 추출은 모두 URL을 검증하고 수동 리다이렉트를 최대 3회만 따른다. 목록 수집은 매 홉에서 URL을 다시 검증하고 robots.txt를 확인한다. 12초 전체 데드라인, 2.5MB 응답 상한, 조건부 요청(`ETag`, `Last-Modified`)을 쓴다. 본문 추출은 분석용으로 별도 제한(12초, 1.5MB, 최대 9,000자)을 적용한다.

두 경로의 robots 실패 처리에는 의도적 차이가 있다. 목록 수집에서 robots 401·403·5xx는 실행을 보류하지만, 본문 추출은 본문만 건너뛰고 요약 분석으로 계속할 수 있다. 자세한 적용 기준은 [데이터·보안 정책](../../policies/data-and-security.md)을 따른다.

## LLM 공급자 운용

DB에 활성화되고 API 키가 있는 공급자를 `priority`, `id` 순으로 시도한다. 공급자가 하나도 없을 때만 `SIGNALIST_LLM_*` 또는 레거시 `SIGNALIST_OPENAI_*` 환경변수를 마지막 수단으로 쓴다. 사용량 날짜는 KST 기준이다.

408, 5xx, 타임아웃, 네트워크 오류와 분당·토큰 한도의 429는 한 번의 실패로 공급자를
제외하지 않는다. 같은 요청을 1초, 2초, 4초 간격으로 최대 세 번 더 시도하고 계속 실패한
경우에만 아래 휴지 시간을 적용해 다음 공급자로 넘어간다. 응답에 일일 한도가 명시된 429,
인증·요청 형식 오류는 같은 요청을 반복해도 해결되지 않으므로 즉시 기록하고 페일오버한다.
Google OpenAI 호환 엔드포인트에는 `reasoning_effort=low`를 전달한다. Gemini 3 Flash의
기본 medium 사고량보다 구조화 뉴스·종목 해석에 쓰는 토큰을 줄이기 위한 공급자별 설정이다.
신규 Gemini 등록 프리셋은 무료 고처리량 모델 `gemini-3.5-flash-lite`다. 기존에 저장된
공급자는 자동 변경하지 않지만, 2026-09-09 429가 발생한 로컬 Google Gemini 공급자는 같은
키와 Base URL에서 14,309자 전체 종목 분석 JSON을 검증한 뒤 이 모델로 변경했다.

| 실패 판정 | 휴지 시간 |
| --- | --- |
| 429 분당·토큰 한도 | 응답 `retryDelay`(15~300초 제한), 없으면 1분 |
| 429 일일 한도 | 다음 KST 자정 |
| 402, quota 성격의 400 | 1시간 또는 다음 KST 자정 중 이른 시각 |
| 인증 오류(401, 403) | 6시간 |
| 요청 오류(그 밖의 4xx) | 30분 |
| 일시 오류(5xx, 408, 타임아웃, 네트워크) | 5분 |

성공 또는 최종 실패한 논리 호출은 공급자 사용량에 포함된다. 내부 재시도와 연결 확인은 앱
집계에 포함하지 않으므로 Gemini의 RPM·TPM·RPD와 같은 실제 할당량은 Google AI Studio에서
확인해야 한다. `daily_limit=0`은 앱 내부 상한 없음이며, 외부 공급자의 한도 없음이라는 뜻은
아니다. 앱 한도를 채운 공급자는 다음 공급자로 넘어간다.

## 진입점

| 수단 | 용도 |
| --- | --- |
| `/` | 소스, 최근 기사 수, 분석 큐, 공급자, 최근 실행 현황 |
| `/news/sources` | 소스 등록·즉시 수집·중지·삭제 |
| `/news/archive` | 기사 검색·필터·본문 분석 실행 |
| `/news/providers` | 공급자 등록·연결 확인·중지·쿨다운 해제·삭제 |
| `/news/lab` | 저장하지 않는 즉석 분석 |
| `/admin/` | 관측 데이터 조회 및 소스·공급자 운영 |
| `crawl_news`, `analyze_news`, `run_scheduler` | 수집·분석·주기 실행 명령 |

현재 일반 뉴스 화면과 변경 POST 엔드포인트에는 별도 로그인 데코레이터가 없다. CSRF 보호는 활성화되어 있으나, 외부에 노출하는 운영 환경이라면 접근 제어를 추가하기 전까지 공개 배포로 간주해서는 안 된다.

## 코드 배치와 변경 안내

| 변경 대상 | 먼저 검토할 위치 |
| --- | --- |
| URL·날짜·HTML·피드 판정 | `backend/news/crawler/` 및 parity 테스트 |
| 수집 순서·DB 기록 | `backend/news/services/ingest.py` |
| 큐 상태·인사이트 저장 | `backend/news/services/insights.py` |
| 공급자 선택·사용량·쿨다운 | `backend/news/services/llm.py` |
| DB 스키마 | `backend/news/models.py`, `migrations/` |
| 화면 입력과 HTTP 흐름 | `forms.py`, `views.py`, 템플릿 |

파서 동작은 고정 회귀 입력으로 검증한다. URL·날짜·본문 추출·감성 계산을 바꿀 때는 기존 기사 식별자와 수집 결과에 미치는 영향을 검토하고, 필요한 경우 입력과 기대 결과를 함께 갱신한다.
