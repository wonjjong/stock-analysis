# 리서치 도메인

## 범위

리서치 도메인은 요청받은 한국·미국 종목의 공개 시장·공시·뉴스 근거를 모아 AI 분석을 만들고, 여러 종목을 팩터와 거시 환경으로 비교한다. 분석과 랭킹 결과는 화면 응답으로만 제공하며 DB에 저장하지 않는다.

## 유스케이스

| 경로 | 기능 |
| --- | --- |
| `/research/lab` | 티커 하나의 시장 스냅샷, 공시·뉴스 근거, AI 분석 |
| `/research/lab/preview` | 외부 데이터·AI 호출 없이 고정 샘플로 분석 결과 UI 확인 |
| `/research/rank` | 2~12개 종목의 팩터 점수·거시 환경 기반 랭킹 |
| `/research/api-test` | DART·SEC 식별자와 공시 조회 확인 |
| `/api/research/stocks/search` | 한국투자증권·SEC 인덱스를 이용한 종목 검색 |
| `/api/research/stocks/<symbol>/analyze` | 종목 분석 JSON API |

## 데이터와 경계

- 시장 스냅샷은 `yfinance`로 시세·변동성·밸류에이션·재무 지표를 조회한다. 1년 일봉에서
  20·60·100일 이동평균과 정배열·역배열·혼조 상태, 최근 120거래일 OHLC 차트를 만든다.
- 한국 종목 공시는 Open DART, 미국 종목 공시는 SEC EDGAR에서 조회한다. 공시 재무는 시장별
  외부 응답을 공통 `FundamentalMetrics`로 변환해 Quality·Value 팩터에 반영한다. 회사
  식별자 인덱스는 캐시하며 갱신 실패 시 유효 캐시를 계속 사용한다.
- 저장된 뉴스 기사와 시장 데이터 제공 뉴스는 `Evidence`로 변환한다. 근거에는 출처와 관측·수집 시각을 포함한다.
- LLM은 근거로부터 상승·하락 논리, 촉매, 무효화 조건, 데이터 공백을 서술할 수 있으나 수치나 사건을 새로 만들면 안 된다.
- LLM을 쓸 수 없거나 호출이 실패하면 데이터 기반 폴백 결과를 반환한다.
- Gemini에 전달하는 추가 지표는 값·단위·출처·기준일과 데이터 공백만 포함한다. 화면용
  설명·수식을 반복 전송하지 않는다. 동일 종목·마지막 일봉·표시 가격·재무 기준일·공시/뉴스
  근거의 성공 보고서는 20분 캐시한다. 요청마다 달라지는 수집시각, 공급자 캐시 상태·거시 조회,
  시가총액·제공 배수의 미세한 반올림 변화는 같은 분석의 캐시 키를 바꾸지 않는다.
  실패 폴백은 캐시하지 않아 공급자 복구 후 다시 분석할 수 있다.

## 단일 종목 분석과 매매 계획

`/research/lab`은 현재가와 20일 ATR, 거시 위험 강도로 기계적 가격 계획을 계산한다. AI는
이 숫자를 만들거나 변경하지 않고 상승·반대 논리와 관점 무효화 조건만 설명한다.

- 진입 검토 구간: `현재가 - ATR×0.55`부터 `현재가 - ATR×0.15`
- 손절 기준: `현재가 - ATR×max(0.8, 1.8 - 위험강도×0.6)`
- 목표 참고가: `현재가 + (현재가-손절가)×max(1.6, 2.2 - 위험강도×0.4)`

가격 계획과 캔들 차트는 투자 지시나 미래가격 예측이 아니다. 증권사 컨센서스 목표가는
현재 수집하지 않으며, 화면의 목표 참고가는 ATR 기반 위험보상 시나리오다.

분석 폼은 제출 즉시 중복 제출을 막고 로딩 상태를 표시한다. 결과 응답이나 브라우저의 페이지
복원 시 로딩 상태를 초기화한다. `/research/lab/preview`는 고정 샘플만 사용하므로 시세,
DART/SEC, 뉴스, LLM 공급자를 호출하지 않는다.

## 랭킹 계약

`rank_candidates`는 가격이 양수이고 유동성 점수 35 이상, 데이터 결측 비율 15% 이하인 후보만 평가한다. Quality, Value, Momentum, Revisions, News 점수를 횡단면 정규화하고 VIX·원/달러·금리·신용스프레드로 만든 위험회피 강도에 따라 가중치를 조정한다.

결과에는 점수·신뢰도·판단·진입 구간·목표가·손절가가 포함된다. 이 수치는 정량 엔진이 결정하며 LLM은 변경하지 않는다. 랭킹 결과는 투자 조언이나 수익 보장이 아니다.

## 종목별 뉴스 검색 (2026-09-08)

단일 종목 분석은 DB 뉴스, Yahoo 종목 뉴스, 국내 Naver/미국 GDELT 검색 뉴스를 합친다.
`stock_news.py`는 검색 조건·관련성·중복 제거·점수화의 순수 도메인 규칙을 담당하며,
`services/news_search.py`는 공통 검색 포트의 HTTP 어댑터,
`services/stock_news.py`는 ORM·검색·캐시 조정,
`services/stock_analysis.py`는 HTML과 JSON이 공유하는 시장·공시·뉴스 수집 유스케이스다.
기존 View의 별도 뉴스 근거 조립은 제거하고 이 유스케이스로 대체했다.

- 종목코드, 시세 회사명, KIS/SEC 회사명·영문명·별칭과 내장 종목 사전으로 검색한다.
  회사 인덱스 실패 시 시세 회사명과 내장 사전으로 계속한다.
- 최근 30일, 공급자별 최대 50건, 최종 최대 12건이다. 제목 관련성 우선, 이후 최신순이다.
  사전의 긴 별칭 우선 규칙과 영문 단어 경계를 사용하며 짧은 티커 단독 일반 단어는 제외한다.
  동명이인·동명 회사의 완전한 의미 판별까지 보장하지는 않는다.
- URL은 기존 추적 파라미터 제거 규칙으로 정규화한다. URL이 없으면 정규화 제목으로 중복
  제거한다. 동일 URL의 분석된 DB 기사는 저장 요약과 감성 점수를 우선한다.
- 외부 기사와 미분석 DB 기사는 기존 규칙 엔진의 제목·요약 감성 점수를 사용한다.
  최종 채택 기사별 점수 평균이 뉴스 팩터, 기사 수가 `newsObservations`다.
  동일한 목록이 AI `Evidence(kind=news)`로 전달된다. 뉴스가 없으면 50점/0건이다.
- 검색 기사 본문은 추가 요청·저장하지 않는다. GDELT는 제목만 제공하므로 제목 수준에서
  평가한다. 규칙 감성점수는 부정문·풍자·문맥을 완전히 이해하지 못한다.
- 외부 검색과 Yahoo 뉴스는 종목·검색어·30일 기간 기준으로 20분 캐시한다. DB는 매 요청
  다시 읽고 최종 선별도 다시 수행한다. 실패·키 미설정은 캐시하지 않는다.
- Naver 키는 `SIGNALIST_NAVER_CLIENT_ID`, `SIGNALIST_NAVER_CLIENT_SECRET` 환경변수로
  설정하고 서버를 재시작한다. 미설정이면 Naver만 건너뛴다. GDELT는 별도 키가 없다.
  DB 마이그레이션이나 신규 패키지는 필요 없다. 다중 워커 공유 캐시는 기존 Redis 설정을 쓴다.
- HTTP 요청은 5초, 응답은 512KiB 상한이며 Naver 별칭 검색은 전체 12초 데드라인을 둔다.
  별칭은 최대 7개와 티커로 제한하고 Naver의 50건 예산을 검색어별로 나눈다.
- 공급자 실패 시 성공한 근거로 분석을 계속하며 공급자 상태와 데이터 한계를 화면·AI 입력에
  포함한다. Yahoo 뉴스 실패도 시세 수집 전체를 중단시키지 않는다.
- `/api/research/stocks/<symbol>/analyze`의 기존 입력과 추천/보고서 필드를 유지한다.
  선택한 대상 뉴스 팩터·관측 건수만 갱신한 뒤 순위를 다시 계산한다. 호출자가 준 가격·재무
  값은 유지한다. 추가 `newsSearch`는 `providers`(provider/status/fetched/accepted/cached/detail),
  `count`, `periodDays`, `cacheTtlSeconds`, `dataGaps`를 제공하고 report에도 `dataGaps`를 추가한다.
  이제 JSON 분석도 선택 종목의 시세·공시를 조회하므로 시세 실패 시 502 오류를 반환한다.
  다종목 랭킹 자체에는 외부 검색을 추가하지 않으며 기존 뉴스 커버리지 가중치 정책을 유지한다.
- 미리보기는 뉴스 3건과 공급자별 상태를 고정 샘플로 표시하고 외부 호출을 하지 않는다.

공급자 시각은 원문 발행일과 다를 수 있다.
[Naver API](https://developers.naver.com/docs/serviceapi/search/news/news.md)의 pubDate는 네이버
제공 시각이며 [GDELT DOC API](https://blog.gdeltproject.org/gdelt-doc-2-0-api-debuts/)의 seendate는
최초 수집 시각이다. 특히 GDELT 근거 요약에 이 한계를 명시한다. 뉴스 전수 검색·원문 분석을
보장하지 않으며 제목/요약에 종목 언급이 없는 결과는 채택하지 않는다.

검증은 도메인 단위 테스트, MockTransport 어댑터 테스트, 캐시·부분 실패·공통 유스케이스·
미리보기 통합 테스트와 전체 pytest/Ruff로 수행한다. 실제 계정 키를 이용한 Naver 호출은
자동 테스트에서 수행하지 않는다.

GDELT 공용 DOC API는 호출 빈도 제한(응답 HTTP 429, 통상 5초당 1회)을 둘 수 있다. GDELT
어댑터는 검색 결과를 최종 반영 한도인 12건으로 제한하고 15초 요청 타임아웃과 전체 24초
데드라인을 사용한다. 429를 한 번 5초 기다려 재시도하며, 계속 거절되면 그 원인을 공급자
상태에 남기고 DB·Yahoo·공시 기반 분석은 중단하지 않는다. 이는 외부 공용 엔드포인트의
IP 제한을 애플리케이션이 제거할 수 없기 때문이다.
2026-09-08 검증 결과: `backend/`에서 `.venv/bin/python -m pytest`는 222 passed, 1 skipped,
`.venv/bin/ruff check .`는 통과했다. 신규 테스트는 `test_stock_news.py`,
`test_news_search.py`, `test_stock_news_integration.py`에 있다.

## 지표와 가정별 가치평가 (2026-09-09)

단일 종목 분석과 네트워크 없는 미리보기에 31개 지표를 제공한다. 가치평가(PER 실적/예상,
PBR, EV/EBITDA, EPS, BPS), 수익성·성장(ROE, ROA, 영업이익률, 순이익률, 매출 성장률),
현금흐름·재무안정성(단순 FCF, FCF 수익률, 순차입금, 차입금/자기자본, 유동비율),
기술·위험(RSI14, MACD/시그널/히스토그램, 볼린저 상·중·하단, 거래량 배율, MA20/60/100,
ATR20, 변동성, 최대 낙폭, 베타)을 나눈다. 기존 이동평균·ATR·위험 지표도 설명 패널에 포함한다.
각 항목의 `용어·계산 기준`은 모바일 터치와 키보드로 펼칠 수 있으며 의미, 계산식, 출처,
기간과 결측 이유를 제공한다. 0은 숫자로 표시하고 결측·적용 불가는 `자료 부족`으로 표시한다.

- `technical_indicators.py`: 프레임워크 없는 일봉 계산. RSI는 Wilder14(최소 15종가,
  평탄=50, 상승만=100, 하락만=0), MACD는 SMA로 초기화한 EMA12−EMA26(26종가), 시그널은
  MACD EMA9(34종가). 볼린저는 SMA20 ± 모집단 표준편차 2배, 거래량 배율은 최신/직전20일
  평균이다. 잘못된 가격·NaN·무한대 이후 연속 유효 구간만 계산하며 부족하면 null이다.
  거래량은 가격과 독립 검증한다. 조정 일봉과 초기화 방식 때문에 일부 MTS와 차이가 날 수 있다.
- `market_data.py`: 기존 Yahoo/yfinance 조회에서 추가 제공 비율과 주당값·주식수·재무 통화를
  읽는다. 추가 연간 재무는 제표별 최신 결산 열을 사용하며 이전 연도의 누락값으로 채우지 않는다.
  같은 기간의 대체 계정은 사용할 수 있다. 재무제표 조회가 실패해도 해당 지표만 비운다.
  값별 결산일을 보존하며 제공 비율의 정확한 기간이 없으면 `미제공`으로 명시한다.
- `indicators.py`: 공시 PER/PBR/순이익률/매출 성장률이 있으면 DART/SEC 값을 우선한다.
  그 밖의 추가 지표는 Yahoo 제공 값 또는 명시된 연간 재무 계산이다. 단순 FCF는
  `OCF − abs(CapEx)`이며 두 값의 기간이 일치해야 한다. FCFE/FCFF로 취급하지 않는다.
  FCF 수익률은 재무·거래 통화 일치가 확인된 경우에만 `FCF / 시가총액 × 100`으로 계산한다.
  차입금/자기자본은 총부채비율과 다르다. 음수 순차입금과 음수 FCF는 보존한다.
- `services/stock_analysis.py`: HTML과 JSON에 같은 `indicators` 컨텍스트를 반환하고 AI
  입력에도 전달한다. 필드는 `groups[].name`, `groups[].metrics[]`의
  `key/label/value/unit/description/formula/source/period/missing_reason`, `dataGaps`다.
  JSON은 추가 `valuationInputs`, HTML은 `valuation_inputs`를 제공한다. 기존 추천 점수와
  ATR 계획의 산식은 유지한다. 추가 지표는 해석 근거이며 점수 가중치를 임의로 바꾸지 않는다.
  AI는 지표 누락을 추측하거나 적정가·성장률·컨센서스를 생성할 수 없다.

`POST /api/research/valuation`은 CSRF 보호된 순수 계산 API다. body는
`{inputs: {price,currency,eps,book_value_per_share,ebitda,cash,debt,shares}, assumptions: {...}}`.
화면에 공급자 기초값·결산일을 표시하고 가정은 빈 상태에서 시작한다. 이 API의 입력은 사용자가
보내는 시나리오 값으로 서버가 시세 진위를 보증하지 않는다. 재계산은 네트워크 수집·AI·DB 저장을
호출하지 않는다. 통화가 일치하지 않거나 확인되지 않으면 화면의 기초 재무 입력을 비운다.

| 가정 키 | 계산 |
| --- | --- |
| `target_pe` | TTM EPS × 적용 PER |
| `target_pb` | BPS × 적용 PBR |
| `target_ev_ebitda` | (연간 EBITDA × 배수 + 현금 − 차입금) / 현재 주식수 |
| `fcff`, `growth_pct`, `discount_pct`, `terminal_growth_pct` | 직접 입력한 정상화 연간 FCFF를 5년 성장·WACC 할인하고 영구가치를 할인한 뒤 현금/차입금/주식수 반영 |

DCF의 영구가치는 `FCFF5 × (1+g)/(WACC−g)`이고 FCFF0부터 연간 일정 성장률을 가정한다.
WACC는 영구성장률보다 커야 한다. 배수는 (0,1000], 성장률은 (-100,100]%, WACC는 (0,100]%로
입력 범위를 제한한다. bool/NaN/무한대와 1e18 초과 절대값은 거부한다. 음수 FCFF의 흑자전환
모형은 지원하지 않는다. EPS/BPS/EBITDA가 양수가 아니거나 기초값이 빠지면 해당 방법만 계산하지
않고 이유를 반환한다. 주주가치가 0 이하이면 음수 목표주가를 제시하지 않는다.

응답은 `methods[]`의 `method/value/upside_pct/formula/reason`과 `dataGaps`다. 가정이 전혀
없으면 빈 methods, 일부 DCF 가정만 있으면 누락 이유, 잘못된 입력은 400 `{error}`를 반환한다.
무한대 등 JSON에 표현할 수 없는 결과는 null로 처리한다. UI는 재계산 중 중복 제출을 막고,
성공·400·통신 오류·15초 타임아웃 뒤 버튼을 복구한다.

계산기는 단순 상대가치·DCF 시나리오이며 증권사 컨센서스나 자동 산출한 적정 배수가 아니다.
EV/DCF는 소수주주지분·우선주·비영업자산 조정을 생략하므로 복잡한 자본구조와 금융업에는
한계가 있다. 연간 재무와 TTM EPS, 현재 주식수의 시점도 다를 수 있다. 기존 가격 계획은 화면과
차트에서 `ATR 목표 참고가`로 구분한다. 무료 접근 가능한 기존 공급자만 이용하며 신규 유료 API,
패키지, 환경변수, DB 마이그레이션은 없다. Gemini 공급자와 모델 설정은 변경하지 않는다.

### 분석실 숫자 표시와 PER 결측 (2026-09-09)

`/research/lab` 결과 카드와 지표 카드는 작은 화면에서 카드 폭보다 길어진 숫자가 잘리지 않도록
한 열까지 줄어들며, 글자 크기와 줄바꿈을 조정한다. 진입 검토 구간의 양 끝 값도 독립적으로
줄바꿈할 수 있다. 1일·1개월·6개월·1년 수익률, 52주 고점 대비, 1년 최대 낙폭과 차트의 당일
수익률은 양수에 `+`와 민트색, 음수에 기존 `−`와 빨간색, 0에 중립색을 적용한다. 색상만으로
상승·하락을 전달하지 않으며 부호를 함께 유지한다. 다른 지표의 값 자체는 투자 방향 신호가
아니므로 기계적으로 양수/음수 색을 지정하지 않는다.

`PER · 실적`은 DART/SEC의 양수 연간 PER 또는 Yahoo의 양수 TTM `trailingPE`가 있어야 하고,
`PER · 예상`은 Yahoo가 제공하는 양수 `forwardPE`가 있어야 표시한다. 적자·EPS 0, 공급자 미제공,
또는 비정상/음수 배수는 저평가로 오해하지 않도록 `자료 부족`으로 처리한다. 예상 PER은 별도
증권사 컨센서스를 수집한 값이 아니라 Yahoo가 제공할 때만 보조 지표로 표시한다.
결측 카드에는 EPS·순이익·시가총액·공급자 비율 중 확인된 원인을 함께 표시한다.

양수/음수 부호와 색상 클래스가 함께 적용되는지를 브라우저로 확인하고, 미리보기 렌더링
회귀 테스트와 전체 pytest/Ruff로 수행한다.

검증: `test_technical_indicators.py`, `test_valuation.py`, 시장 어댑터·공통 유스케이스 테스트로
수식, 결측, 통화, 기준일, 비유한 입력, CSRF, 미리보기·AI 컨텍스트를 검증한다.
